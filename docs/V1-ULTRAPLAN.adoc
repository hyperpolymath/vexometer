== The ask, restated

Make this repository the premier online destination for *LLM user-experience and
cognitive/information-ergonomics measurement* — an LM-Arena-style arena with a
Social Blade-style public statistics layer — served under *irritation-surface.dev*,
delivered *strictly* on the estate's own machinery: `rsr-template-repo` +
`standards` compliance, the proven tests/benches discipline, `cicd-squabbler`
for CI legitimacy, `panic-attack` and `pons-asinorum` as standing screens, full
community health (issues, security/quality, rulesets, policies), and a
deployment target of Verpex OpenLiteSpeed + Varnish with the estate's
HTTP capability gateway and a consent-aware web posture.

This document is the recon receipt and the plan to get there. Every claim about
the current tree carries the file or command that produced it. Every claim about
the future carries an acceptance test.

== The product: irritation-surface.dev v1

=== Positioning

Capability leaderboards (MMLU, HumanEval, Arena Elo) answer *what models can
do*. Nothing premier answers *what it feels like to work with them* — time
waste, sycophancy, hedging, paternalism, hallucination, refusal theatre,
attention intrusion, information density, completion integrity, recovery
competence. That is ISA's ten dimensions, and the letter to LMSYS
(`vexometer/docs/letter_lmsys_arena.adoc`) already made the case. v1 is that
case, owned and operated under irritation-surface.dev.

Three public surfaces, one honesty spine:

[cols="1,3,3", options="header"]
|===
| Surface | What it is | Estate-native anchor

| *1. The Arena*
| Blind head-to-head *experience battles*: two anonymised models get the same
  probe/scenario set; the user votes on ergonomics criteria (respect for time,
  information density, calibration, non-paternalism, coherence); automated ISA
  pre-scores are revealed *after* voting. Bradley–Terry/Elo per dimension and
  overall. Anti-gaming: rate limits, vote provenance (Vext-verifiable where
  opted in), anomaly flags, dispute flow via issues.
| Probe suite + scenario-set registry (`f1` provenance ruling),
  `vexometer-trace-v1`, efficacy validator as the score oracle.

| *2. The Observatory (leaderboard)*
| Sortable ISA leaderboard: overall + 10 dimensions, *every number dated, with
  repeats and confidence intervals* (the post-#101 reproducibility doctrine
  made product law). Methodology page states formula + weights; a
  `Doc == tool` test enforces site numbers recompute from `Calculate_ISA`.
| `Compare_Models` (Welch + bootstrap CI), METRICS.adoc weights, the
  issue-101 exact-value test pattern.

| *3. Social Blade layer (profiles & grades)*
| Per-model public "channel" pages: letter grades per dimension (fixed,
  published score→grade bands), irritation rank + 30/90-day trend charts
  (static SVG), growth/regression deltas, verified-run badges (trust-manifest
  hashes), run history, an embeddable badge + public JSON, and *satellite
  efficacy pages* (which interventions measurably move which metrics, via
  `vexometer-efficacy-v2` frontier records) — the "channels" of the
  intervention ecosystem.
| Trust manifests, frontier records, SARIF/JSON reports, groove manifest
  feed-verification capability.
|===

=== Product principles (non-negotiable)

. *Reproducible or unpublished* — every leaderboard number is a dated run with
  N repeats and an interval; snapshots are content-addressed and re-derivable.
. *Consent-aware web* — no tracking, no third-party scripts, no consent banner
  theatre: nothing to consent *to*. Where the AIBDP / HTTP 430 posture from
  `metadatastician/consent-aware-web` (ADR-005) applies, the site dogfoods it
  at `/.well-known/aibdp.json`. Votes require no account; local-first providers
  preferred; TAI is measured *on ourselves*.
. *Heuristic ≠ proof* — pons-asinorum's honesty rule applied to the product:
  pattern-based findings are labelled as heuristic evidence tiers; human-eval
  numbers carry inter-rater stats; nothing is dressed as formal.
. *Ergonomics of the site itself* — WCAG 2.2 AA minimum (stretch the existing
  target from 2.1), fast static-first pages under Varnish, readable information
  density (the site must pass its own verbosity/ergonomics review).
. *Open method, open data* — probe suites, weights, grade bands, and run
  snapshots are versioned in-repo; disputes are issues.

== Binding estate constraints (from standards + rsr-template-repo)

. *Licence/SPDX Manual-Only* — new files born with correct SPDX (docs
  `CC-BY-SA-4.0`, code/tests `MPL-2.0`); no header sweeps of existing files.
. *A2ML is retired* — no new `.a2ml` files, no new A2ML content. Legacy
  `.machine_readable/6a2/` stays as-is; new machine-readable state goes in the
  current formats the standards registry names.
. *Language policy* — no Python, no TypeScript. Ada is legacy-but-maintained
  (fix in place, no new pure-Ada projects). New web/server code: Rust
  (already the house default), Elixir for the gateway integration tests where
  the gateway itself is exercised; Idris2/Zig where ABI seams demand it; the
  static site is HTML/CSS + minimal JS only where the arena vote UI needs it,
  and that JS is hand-written, dependency-free, and consent-aware.
. *Trust manifests* — any edit to hashed files regenerates manifests in the
  same change (`just trust-generate`); `run-must-gates.sh` verifies.
. *Conventional commits* — feed the changelog workflow (`fix(data):`,
  `feat(arena):`, `docs(plan):` …).
. *Doc == tool* — numbers printed anywhere (README, site, badges) are enforced
  by exact-value tests (efficacy #69 ruling).
. *Stopping rule* (issue #96) — pre-existing reds are issues, not merge
  blockers; G1 is now the named one and gets closed in P0.
. *Readiness grades* — ARG/FRG/CRG/TRG from `standards`; this repo tracks CRG
  (G3) and the new web components get TRG evidence (toolchain) + CRG evidence
  (tests per taxonomy).

== Risks and honest caveats

* *Measurement validity is the real risk.* Regex/probe heuristics are tested,
  not proved (EXPLAINME caveat stands). A public leaderboard amplifies error.
  Mitigation: evidence-tier labelling (pons doctrine), intervals on everything,
  dispute-driven re-runs, and refusing to rank where N < threshold.
* *Arena gaming.* Any voting surface gets attacked. Mitigation: no accounts =
  less value in farming; rate limits; anomaly flags *labelled heuristic*;
  public vote-log digests; post-v1 consideration of proof-of-personhood — not
  v1.
* *Single-maintainer capacity.* The plan sequences P0–P3 so every phase
  leaves a shippable increment (green CI → levelled repo → honest corpus →
  public site). P4–P5 are additive to a product that already exists at P3.
* *Verpex constraints* (allowed runtimes, process model, Varnish position)
  are assumed, not verified. Mitigation: WS-5.1 begins with a bring-up probe
  before any app code depends on it; D-4 keeps a policy-only fallback.
* *Estate coupling.* Reusables from `standards` are pinned; a broken upstream
  can red this repo (nexia-list#100 precedent). `squabble chains` runs before
  every pin bump.
* *Formal-posture gap (G7).* v1 does not close it; it routes proof effort to
  the scoreboard math (SPARK on `ISA_Calculator`) post-v1 and keeps the ABI
  no-escape-hatch invariant everywhere it already holds.
* *Brand confusion* across vexometer/ISA/irritation-surface.dev is managed by
  NAMING.adoc (WS-1.5), not by renaming protocol IDs.
